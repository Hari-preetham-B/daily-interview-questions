### 🌅 Morning (2026-10-27) — DSA

**You are given a binary tree where each node contains an integer value. The tree is not guaranteed to satisfy any ordering property. Define a subtree as any node together with all of its descendants. A subtree is considered a Binary Search Tree (BST) if for every node, all values in its left subtree are strictly less than the node’s value, and all values in its right subtree are strictly greater than the node’s value. Write an algorithm to find the size (number of nodes) of the largest subtree that is a BST. The algorithm should run in O(n) time where n is the number of nodes in the tree.**

<details>
<summary>💡 Hint</summary>

Traverse the tree in post‑order. For each node, combine information (size, min, max, isBST) from its left and right children to decide if the subtree rooted at that node is a BST.

</details>

<details>
<summary>✅ Answer</summary>

The optimal solution is a single post‑order traversal that returns, for every node, four pieces of information: whether the subtree is a BST, its total size, the minimum value in the subtree, and the maximum value. For a leaf node, the subtree is trivially a BST of size 1, with min = max = node.val. For an internal node, the subtree is a BST iff the left subtree is a BST, the right subtree is a BST, the maximum value of the left subtree is less than node.val, and the minimum value of the right subtree is greater than node.val. In that case the size is left.size + right.size + 1, min is min(left.min, node.val), and max is max(right.max, node.val). If the subtree is not a BST, we still propagate the largest BST size found so far. The maximum size encountered during the traversal is the answer. This runs in O(n) time and O(h) space for recursion depth, where h is the tree height.

</details>

### 🌙 Evening (2026-10-27) — CSE Core

**What is the purpose of a page replacement algorithm in virtual memory systems, and how do the Least Recently Used (LRU) and Clock (Second-Chance) algorithms differ in terms of implementation complexity and performance trade‑offs?**

<details>
<summary>💡 Hint</summary>

Consider how each algorithm decides which page to evict when a page fault occurs, and think about the data structures they require.

</details>

<details>
<summary>✅ Answer</summary>

A page replacement algorithm selects a victim frame to free when a page fault occurs and no free frames are available, aiming to minimize future faults. LRU evicts the page that has not been accessed for the longest time; it provides good approximation of optimal replacement but requires tracking exact access order, often using a stack or timestamps, which adds overhead. The Clock algorithm approximates LRU by arranging frames in a circular list with a reference bit; the hand sweeps the list, giving each page a second chance (clearing the bit) before eviction, resulting in lower hardware/software overhead and comparable performance in practice, though it may evict a page that was more recently used than LRU would.

</details>
