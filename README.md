### 🌅 Morning (2026-11-08) — DSA

**Given an unsorted integer array, find the length of the longest sequence of consecutive integers that appear in the array. For example, for [100, 4, 200, 1, 3, 2], the longest consecutive sequence is [1,2,3,4] so the answer is 4.**

<details>
<summary>💡 Hint</summary>

Use a hash set to look up elements in O(1) time. For each element, check if it could be the start of a sequence (i.e., its predecessor is missing) and then count how long the chain continues.

</details>

<details>
<summary>✅ Answer</summary>

A linear‑time, linear‑space solution uses a set to store all numbers. Iterate over each number; if `num-1` is not in the set, `num` is the start of a new consecutive chain. Then repeatedly increment `num` while `num+1` exists in the set, counting the length. Keep the maximum length seen. The code in Python:

python
def longestConsecutive(nums):
    s = set(nums)
    best = 0
    for num in nums:
        if num - 1 not in s:          # start of a sequence
            cur = num
            length = 1
            while cur + 1 in s:
                cur += 1
                length += 1
            best = max(best, length)
    return best

This runs in O(n) time and uses O(n) additional space for the set.

</details>

### 🌙 Evening (2026-11-08) — CSE Core

**What is the difference between TCP's slow start and congestion avoidance phases, and how do they affect throughput after a packet loss?**

<details>
<summary>💡 Hint</summary>

Consider how the congestion window grows during each phase and what happens when a loss is detected.

</details>

<details>
<summary>✅ Answer</summary>

In TCP slow start, the congestion window starts small and grows exponentially, doubling each RTT until it reaches a predefined threshold. After that, congestion avoidance uses additive increase, adding roughly one maximum segment size per RTT. When a packet loss occurs, TCP assumes congestion and performs multiplicative decrease, reducing the congestion window to a fraction (typically half). This drop leads to a sudden decrease in throughput; slow start then re‑increases the window, producing a sawtooth pattern in throughput over time.

</details>
